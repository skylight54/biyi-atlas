# 避役图志 · Biyi Atlas

避役图志是为 **Minecraft Java 版 1.20.1 · Forge 47.4.8** 制作的 RPG 地图模组。作者可以在游戏里沿城墙圈出城镇，把桥头和地牢入口连成路网，再用世界地形生成底图。玩家在探索中驱散水墨迷雾，查看地标，沿已绘制的道路前往目的地。

- **制作与美化。** 作者可撤销编辑，发布区域底图，也可通过 MCP 导入 AI 美化候选，为每个大区域挑选展示图。
- **交接地图。** 用 `/biyi_atlas_local export_project mymap` 导出一个 `.biyi.zip`，连同对应的 Minecraft 世界交给下一位作者。区域、道路、已发布底图、美化候选和自定义作者素材随地图工程打包。[完整地图工程分享](docs/完整地图工程分享.md)
- **参与开发。** A 批已集成常驻小地图和按身份打开的 M 键大地图。后续批次负责原生实景圈区及局部楼层。分支分工、依赖和验收见[开发契约与任务卡](docs/协同开发/开发契约.md)，界面见[地图设计稿](docs/地图界面设计/设计说明.md)。

下文操作说明对应 `0.1.0` 开发版、网络协议 5，玩家空手即可使用小地图和 M 键大地图。联机时服务器和玩家应使用同一份构建产物。

## 1. 安装与目录约定

当前开发和测试环境为 **Minecraft 1.20.1、Forge 47.4.8、Java 17**。请使用 Forge 版；当前没有 Fabric/NeoForge 发行包。普通使用不需要 Python、AI 客户端或其他地图模组；Python 只用于可选的作者 MCP 工具。

1. 完全退出游戏，将 `biyi_atlas-0.1.0.jar` 放入实例的 `mods/`。
2. 联机时，**服务器和每一位玩家的客户端都要安装同一份模组**。局域网加入者也需要自行安装。
3. 更新时完全关闭相关游戏/服务器进程，再替换旧 JAR。不要在运行中覆盖 JAR；同一实例也不要同时保留多个版本的本模组。

本文统一使用以下占位符，复制路径时请换成自己的实际目录：

| 占位符 | 含义 |
| --- | --- |
| `<实例>` | 本次启动实际使用的游戏目录，里面有 `mods/`、`config/`、`logs/`。开启版本隔离时，通常是 `.minecraft/versions/<版本目录>/` |
| `<世界目录>` | 单人一般为 `<实例>/saves/<存档文件夹>/`；专用服务器为实际使用的世界文件夹，常见名称是 `world/` |
| `<世界key>` | 客户端区分存档/服务器用的目录名，见下表；不是随意填写的显示名称 |
| `<服务端>` | 专用服务器根目录，里面有 `mods/`、`config/` 和世界文件夹 |

| 场景 | 世界key 示例 |
| --- | --- |
| 单人 | `sp_<存档文件夹名>`，例如 `sp_rpg_world` |
| 多人 | `mp_<净化后的服务器地址>`；可在 `biyi_atlas/authored/` 中查看实际生成的目录名 |
| 尚未识别世界 | `unknown`；正常进世界后应使用对应的 `sp_…` 或 `mp_…` |

请通过启动器打开该实例的游戏目录，避免把文件放入另一套 `.minecraft`。

## 2. 玩家怎么使用

1. 进入已发布区域后，右上角的小地图跟随玩家。按 **M** 展开大地图；已获编辑权的创造玩家进入作者工作台。键位可在游戏的按键绑定中修改。
2. 两种大地图的左上角都有“设置”。可开关 HUD、选四角位置、切换北向朝上或随玩家转向、显示已知标记，并在 **0.5× 到 3×** 之间调整 HUD 倍率。偏好保存在实例的 `biyi_atlas/settings.json`。
3. 玩家在大地图中拖动平移、滚轮缩放。点“世界总览”看已开放区域，点击区域进入；“定位”将镜头移回玩家。区外默认打开总览。
4. 点地标查看小卡片。有已标注入口时可追踪入口。点击允许标记的空白位置，填名称和备注后保存私人路标。再次点路标可编辑或删除，“恢复路标”取回最近删除的一项。Esc 优先收起卡片，M 关闭大地图。
5. 私人路标按世界、玩家 UUID 和维度保存在 `biyi_atlas/data/<世界key>/players/<UUID>/<维度命名空间>/` 下；例如主世界的数据文件为 `minecraft/overworld.nbt`。旧维度文件中的既有路标仍可读取。

作者准备并发布区域底图后，玩家才能查看可见范围内的地形。地标、区域解锁与路线取决于作者发布的地图内容。

**解锁演出：** 使用许可证或获得管理员的新区域授权后，地图会自动打开并聚焦该区域，水墨云雾从内部向外消散，随后显示区域名称。空格、Enter、Esc或鼠标操作可跳过，M可关闭地图；登录/重连不会重播已有解锁。未解锁的子区域仍保留迷雾。作者可用下方预览命令重播已解锁区域的演出，不必反复锁区。

## 3. 作者从零制作一张地图

### 3.1 打开作者地图

进入工作台需要处于创造模式，且客户端已收到服务端的编辑授权。`/biyi_atlas wand`、`/biyi_atlas author` 等管理命令本身要求权限 2；开启作弊的单人世界或 OP 可直接使用。

- `/biyi_atlas wand`：获取地图魔杖，右键打开作者地图。
- `/biyi_atlas author`：直接打开作者地图。
- `/biyi_atlas_local author`：在服务端已允许编辑时，本地打开作者地图。

左上角“设置”调整个人偏好；工作台提供对象树、属性、编辑工具、工程设置和 MCP 状态。侧栏可以收起，也可以在其中滚动。

### 3.2 建立大区域和子区域

1. 在“区域”中选择“绘制区域”（“工具 → 画区域”也可）。
2. 在地图画布**右键逐个添加顶点**，按 **Enter** 闭合。至少需要 3 个有效顶点；Esc 取消未完成的绘制。
3. 左键选择区域，在“属性 → 编辑信息”设置名称、父区域、层级、许可证 id、默认解锁等。
4. 选中准备给玩家使用的大区域，点“设地图范围”，或在属性中将“地图范围单位”设为“是”。普通小分区无需都设为独立地图范围。
5. 在大区域内部继续绘制可建立子区域，随后检查父区域归属。同层不兼容的重叠会被拒绝。

小区域边界默认隐藏，作者选中时显示编辑边界；区域文字使用细描边，不使用大块实色底框。缩小时部分小区域/路标名称会减少显示。

### 3.3 一键生成并发布地形底图

1. 在区域树选择一个已设为地图范围的大区域。
2. 点“一键加载区域”，等待区域准备完成。作者不需要沿边界跑一遍。
3. 完成后自动发布；确认状态显示区域底图已载入且采样数量有效，再进入“玩家预览”检查。
4. “发布底图”可手动增量发布已有调查结果；它不能代替整区加载来补齐尚未调查的地方。
5. 需要停止任务时点“取消准备”。取消不会把半成品当成完整底图发布。

当前整区准备只支持**主世界、地表层 0**。一次只准备一个区域；区域包围盒超过 32768 个区块时需拆分。任务可能加载或生成区块，大区域会耗时并增加服务器负载，请等待进度完成。

### 3.4 放置地点、制作道路和路标

- **地点**：“工具 → 放置”选择素材，再在画布右键放置；左键选中后可编辑名称、所属区域、层级等。“放传送点”用于可传送地点。
- **道路**：“画道路”后右键连续加点，Enter 完成；选中道路后编辑宽度/线型等。也可以用 **R** 开始/结束记录行走路径。
- **路网**：使用工具页“路网”中的节点、端点吸附、交叉点、简化等操作组织可导航的道路；完成后实际规划一次路线检查连通性。
- **路标**：通过“路标”页管理；`/biyi_atlas pointwand` 获取路标魔杖，可对实体/NPC标注。路标和“地点”使用不同的存储位置，分发时见第 7 节。
- **区域解锁**：选中区域后使用锁定/解锁按钮，或用许可证、管理员命令授权。请检查要素的所属区域，避免把应隐藏的内容挂到错误的父区。

地图不是编辑世界方块的工具：区域边界、路线、标签和图标属于地图内容。

### 3.5 删除、撤销和重做

| 操作 | 入口 |
| --- | --- |
| 编辑已选对象 | 属性中的“编辑信息”，或按 E |
| 删除已选对象 | Delete，或作者模式下 Shift+右键 |
| 撤销作者编辑 | Ctrl+Z，或“工具 → 撤销编辑” |
| 重做作者编辑 | Ctrl+Y / Ctrl+Shift+Z，或“工具 → 重做编辑” |
| 恢复最近删除的路标 | “路标 → 撤销路标删除” |
| 取消未完成的线条/区域 | Esc |
| 导出完整地图工程 | 作者“导出完整地图工程”按钮，或 `/biyi_atlas_local export_project mymap` |

作者历史按实际保存记录，最多保留最近 **50 步**，跨重启有效。撤销区域级联删除时，子区域、道路归属和对应删除记录一并恢复。撤销后继续新编辑会清除重做分支。绘制中的线条/区域应先完成或取消。

路标删除使用独立的最近 50 条恢复记录，可跨重启恢复原位置、信息、列表位置和置顶；该入口不提供路标重做。撤销不恢复世界方块、不回滚探索地形，也不撤回底图发布或美化候选切换。新功能无法恢复上线前没有保存过历史的旧操作。

## 4. 文件夹总览：哪些是资源，哪些是存档

以下目录会按使用情况生成，不必手工建出所有文件。`.nbt` 是程序保存的数据，不是 PNG 的投放目录。

### 客户端实例目录

```text
<实例>/
├─ mods/biyi_atlas-0.1.0.jar
├─ resourcepacks/                         # 可选的公共贴图/内容资源包
├─ config/biyi_atlas/
│  ├─ regions.json                       # 外部预设内容
│  ├─ places.json
│  ├─ roads.json
│  └─ exported/<世界key>/content.json      # 导出结果，不是作者主库
└─ biyi_atlas/
   ├─ settings.json                      # 本机显示/迷雾等设置
   ├─ authored/<世界key>/
   │  ├─ content.json                    # 作者编辑主库
   │  ├─ content.json.history.json       # 作者撤销/重做历史
   │  └─ content.json.bak.v<n>           # 旧格式迁移备份（有迁移时才出现）
   ├─ data/<世界key>/<维度>.nbt           # 本地调查、路标、置顶及路标删除记录
   ├─ unlocked/<世界key>.json.nbt         # 区域解锁的客户端缓存
   ├─ authoring/<世界key>/icons/*.png     # 游戏内导入的自定义标记图标
   ├─ authoring/<世界key>/locations/      # 旧俯视图生成资源，兼容保留
   ├─ authoring/<世界key>/import/         # 旧图片导入资源，兼容保留
   └─ ai_bridge/
      ├─ heartbeat.json                  # MCP连接心跳
      ├─ request.json / response.json    # MCP单次请求/回执
      ├─ map.json / map.png              # 最近导出的地图内容/实际截图
      ├─ backups/*.json                 # MCP道路样式编辑前备份
      ├─ art-export/base.png            # 本次导出的真实区域底片
      ├─ art-export/manifest.json        # 底片坐标、边界和版本信息
      └─ art-upload.png / art-upload.json # 本次展示图导入的暂存文件
```

例如主世界的维度文件名为 `minecraft_overworld.nbt`。`ai_bridge` 中的“最近一次”文件会被后续请求覆盖；需要保留的底片、截图和生成原稿请另存到自己的项目素材目录。

### 世界/服务器保存的数据

```text
<世界目录>/
├─ data/
│  ├─ biyi_atlas_content.json            # 服务端权威地图内容
│  └─ biyi_atlas_terrain/
│     ├─ <区域哈希>.nbt                 # 已发布区域地形底图
│     ├─ <区域哈希>.art.nbt             # 旧单图文件，兼容保留
│     └─ <区域哈希>.art.nbt.gallery/
│        ├─ index.nbt                   # 候选名称、版本及当前选择
│        └─ <候选id>.nbt                # 候选PNG与配准信息
└─ playerdata/<uuid>.dat                # 各玩家的服务端解锁数据
```

区域哈希由区域 id 计算，**不是区域显示名称**。更改名称不需要重命名文件。底图与展示图库应随世界一起保留；只发作者 `content.json` 不会带上这些地形/美术数据。

## 5. 自定义图标、公共贴图放在哪里

### 5.1 仅在当前作者客户端使用

推荐在“工具”中点“选标记图…”导入 **PNG**，建议使用 **32×32、透明背景**。导入后从素材格选择，再放置地点。程序会将副本保存到：

```text
<实例>/biyi_atlas/authoring/<世界key>/icons/
```

不建议手动改导入后生成的文件名，程序会生成安全名称。将 PNG 手动复制到此目录后，需要重新进入世界让图标列表重新加载；优先使用导入按钮。

### 5.2 给所有玩家分发图标

**作者本地导入的 PNG 不会随区域/道路 JSON 自动传给其他玩家。** 公共图标推荐做成资源包，并让每个客户端启用。

假设地点 JSON 的 `icon` 值为 `my_inn`，公共资源包结构为：

```text
biyi-map-resources.zip
├─ pack.mcmeta
└─ assets/biyi_atlas/textures/atlas/marker/my_inn.png
```

`pack.mcmeta` 示例：

```json
{"pack":{"pack_format":15,"description":"避役图志地图资源"}}
```

文件名使用小写英文、数字、下划线等安全字符，`icon` 中填写不含 `.png` 的标识。**保留已有导入图标时，以导出 JSON 里的实际 `icon` 值命名公共 PNG**，不要按显示名称猜测文件名。如果旧 `icon` 包含中文、空格等非法资源字符，应先在副本中统一改为安全标识并配套重命名公共PNG；显示名称仍可使用中文。已有本地动态图标的客户端优先使用本地图标；其他客户端从上述公共路径读取。

动态注册使用的 `textures/generated/icons/…` 与公共回退查找路径不同，仅把本地 `icons/` 目录照搬到资源包同名目录不能保证其他玩家显示。

当前内置城镇、森林、危险等符号主要由代码绘制。若要使用自己的造型，请创建一个新的自定义图标标识；替换旧内置 PNG 不一定改变这些内置符号。

## 6. AI美化展示图与MCP（作者可选）

**底图是保底层，展示图是可切换的美术层。** 不接 AI 也能使用地图、路网和区域功能。把美化 PNG 放进 `icons/`、旧 `import/` 或 `biyi_atlas_terrain/` 都不会自动启用，必须经过导入校验。

### 6.1 连接MCP

需要一个支持 **stdio MCP** 的 AI 客户端，以及能运行 `tools/atlas_mcp.py` 的 Python 3 环境（脚本使用标准库，无额外 Python 包）。将脚本保留在固定位置；它不包含在 JAR 中。普通玩家不需要安装这些工具。

在 AI 客户端中添加如下服务；字段格式可能因客户端而异，两个绝对路径均需换成自己的：

```json
{
  "mcpServers": {
    "biyi-atlas": {
      "command": "python",
      "args": [
        "D:/MapTools/atlas_mcp.py",
        "--game-dir",
        "D:/Minecraft/versions/1.20.1-Forge_47.4.8"
      ]
    }
  }
}
```

若系统找不到 `python`，将 `command` 改为 Python 可执行文件的绝对路径。连接后进入有编辑权限的世界，保持地图界面打开，作者“MCP”页可查看连接状态、最近操作和准备进度。文件桥默认不开放网络监听端口。

### 6.2 从真实底片生成并导入候选

1. 选择大区域，一键加载并等待完整底图就绪。
2. AI调用 `capture_map`，用返回的 `request_id` 调用 `read_map`，取得当前 `revision`、区域 id、真实截图和地图内容。
3. 对活动区域调用 `export_art_bundle(area, revision)`，导出 `base.png` 和 `manifest.json`。**立即另存一份**，后续导出会覆盖工作目录。
4. 将真实底片和世界信息交给图像生成工具。保持坐标范围、朝向、水陆位置和配准，不裁切、旋转或移动地理要素；不要在图中生成文字、图标和道路，这些由模组动态叠加。
5. 将成品保存为独立 PNG，例如 `D:/MyMap/art/region_a/candidate_01.png`。当前每轴最多 **2048 像素**，单图最多 **3 MiB**；服务端还会裁剪并重新编码，也需满足大小限制，建议预留体积余量。
6. 保留原 manifest 的区域、边界和底图指纹；可额外添加 `variantName` 为候选命名，例如 `"variantName": "雪山细描版"`。不要手改 `shape` / `base` 来绕过失效校验。
7. 再次拉取当前 revision，调用 `import_presentation(area, revision, png_path, manifest_path)`。本机脚本需能访问这两个文件路径。
8. 导入回执“已提交”只是开始；再次抓图，确认实际显示。成功后候选保存在世界图库中，不依赖原 PNG 一直留在上传路径。

每个大区域最多保留 **32 张候选**；导入新图会追加并选中，已有候选保留，相同编码内容去重。旧单图会迁移为“原展示方案”。

**坐标校准（协议5）：** AI可能保持外形却移动内部地形。现在可在原manifest额外添加`registration: [a,b,tx,c,d,tz]`，表示归一化源图坐标到原地图坐标的仿射映射：`x=a*u+b*v+tx`、`z=c*u+d*v+tz`，正z向南。原区域边界、世界范围和base/shape指纹保持不变；校准随候选和工程包保存。同一PNG可保留不同校准方案。默认省略即原映射。导入仍按校准后的实际世界位置裁剪到已知区域，边缘不会循环采样。使用前后应核对多处地标；整体校准不能消除AI局部重画带来的误差。详见[美化图坐标配准](docs/第十九批-美化图坐标配准.md)。

在作者地图选择大区域，进入 **“属性 → 编辑信息 → 成品展示方案（大区域）”**，循环切换“保底地形”和兼容候选。选择由服务端保存。区域边界或底图指纹变化后，旧候选保留但不再作为匹配图使用，应重新导出/生成。存在需要隐藏的未解锁子区域时，普通玩家可能回退到底图。

### 6.3 已提供的MCP工具

| 工具 | 用途 |
| --- | --- |
| `capture_map` / `read_map` | 请求并读取真实截图、地图内容和状态 |
| `show_map` | 切换作者/玩家预览及指定面板 |
| `prepare_area` | 请求整区准备 |
| `publish_area` | 请求发布已有区域底图 |
| `export_art_bundle` | 导出完整区域的底片与配准信息 |
| `import_presentation` | 导入可选美术候选 |
| `style_road` | 修改指定道路样式，保留路线点位，编辑前备份 |

编辑工具使用 revision 校验，地图改变后要重新读取；同一时间只排队一个请求，请求约 60 秒过期。出现 `pending` 时先保持地图打开并等待读取，不要连续重复提交。每次修改后重新抓图，不能用旧截图判断效果。

MCP提供读取、操作和验收通道，**不内置图像生成模型，也不会自动重画全部路网**。AI客户端是否具备图像生成能力取决于所用工具。

## 7. 给别人使用：怎么打包、备份和搬迁

### 联机游玩

- 服务器与每位玩家安装同一构建的 JAR。
- 作者在该服务器制作并保存区域/道路/地点，内容会按权限同步；整区底图和美化候选走各自的准备/发布/导入流程。
- 公共自定义图标额外通过客户端资源包分发。路标在当前版本主要位于客户端的维度 NBT，不要假定“作者扫描出的路标”已经变成全服共享地点；公共导航信息建议制作成作者地点。
- 多位作者应轮流制作。当前不是多作者实时协同合并系统，不建议同时覆盖同一份内容。

### 分发一张已经做好的RPG世界（推荐）

完全退出后，提供：

1. 同一份模组 JAR 和 Minecraft 世界目录，尤其保留其中的 `data/biyi_atlas_content.json` 与整个 `data/biyi_atlas_terrain/`。
2. 公共图标/内容资源包，放入接收者的 `resourcepacks/` 并启用。
3. 若接收者继续编辑，附上作者 `authored/<世界key>/` 目录及历史，放到接收者实际对应的世界key下。
4. 若要保留客户端调查、路标和路标删除历史，附上对应 `biyi_atlas/data/<世界key>/`。玩家个人解锁数据不应随意用作者的账本覆盖；按地图设计配置默认解锁或发放许可证。

存档文件夹改名会改变单人世界key；复制作者内容、图标或路标目录时需对准新key。**美术原稿不等于发布成品库**，只发 `candidate_01.png` 不能代替世界中的候选 NBT。

### 只分发预设区域/道路/地点

优先使用文首的单文件工程分享。以下仅为手动制作静态资源包的旧流程：先导出合并内容。可按 `Regions`、`Places`、`Roads` 各段拆成对应 JSON，放入 `config/biyi_atlas/{regions,places,roads}.json`，或资源包的 `assets/biyi_atlas/atlas/{regions,places,roads}.json`。例如 `regions.json` 保留 `{"Regions":{"schema":2,"list":[…]}}` 的结构（`…` 需替换成真实数组内容，不是可粘贴的 JSON）。

客户端本地加载优先级为：内置/资源包 → config → 对应世界的 authored，并应用作者删除记录。**联机时世界内权威内容还会覆盖旧来源**，已存在权威副本的世界不会仅因替换低优先级配置就丢弃新内容。离线恢复/搬迁前应同时核对客户端作者库和世界权威文件。

预设 JSON 不包含已发布地形、美化图或实体建筑；坐标不同的世界也不会自动搬动点位。首次上线建议先在世界副本中由作者打开并确认保存，再准备底图和核对玩家显示。

### 日常备份

退出游戏/停服后，备份整个世界，以及作者对应的 `authored/<世界key>/`、`data/<世界key>/`、`authoring/<世界key>/icons/` 和使用中的资源包。需要继续生成美术时，还应备份另存的底片、manifest、候选原稿与提示词。

迁移 `.bak.v<n>` 是格式升级备份，不是每次删除都会生成的快照。撤销历史也有步数上限，不能代替长期备份。游戏运行时不要手改作者 JSON、历史或世界 NBT，以免内存内容和磁盘副本互相覆盖。

## 9. 常见问题与当前范围

| 现象 | 优先检查 |
| --- | --- |
| M没反应或打开其他模组 | 按键绑定是否冲突；重新绑定避役图志地图键 |
| 玩家只有区域/路线，没有底图 | 是否选中地图范围、整区准备是否完成、服务端是否收到发布结果、区域是否解锁 |
| 作者有图但玩家没有 | 区分本地调查预览与已发布底图；另查锁区和子区域隐藏规则 |
| 导入美化图失败 | 是否PNG、尺寸/体积合规、manifest是否匹配、整区底图是否完整、revision是否已变化 |
| 切换美化图后仍显示地形 | 候选可能过期、视图关闭展示层，或玩家有未解锁子区域；查看地图状态 |
| 自定义图标别人看不到 | 本地icons不会自动同步；检查资源包路径和实际icon标识 |
| 删除后重进又像旧版，或离线改文件无效 | 是否改错世界key、是否存在更高优先级的世界权威文件；不要只删一个副本 |
| Ctrl+Z提示没有历史 | 仅有功能启用后的实际保存才有记录；路标删除用独立入口；未完成绘制应先结束 |
| 撤销提示地图被外部修改 | 为避免覆盖其他改动，历史操作被拒绝；先备份，核对当前文件和历史，不要强删版本信息 |
| 内容进入只读保护 | 查看 `logs/latest.log` 中的版本/迁移提示，使用匹配构建，先备份再处理 |
| 整区加载慢 | 检查任务进度和区域大小；可取消后拆分，不要反复排队 |
| MCP一直pending | 指向正确实例、具备作者权限、地图保持打开；检查是否有未完成请求和回执id |

当前底图是采样绘制结果，不能完整还原所有模组材料或地下建筑。美化图高倍放大可能模糊，保底图高倍下仍可能出现图块接缝；旧映像图入口已停用，不建议再按旧说明使用 capture/外部大图作为新展示层。不要把“候选生成成功”当成位置和路线已经自动正确配准，导入后应实际检查。

单人环境的整区发布、候选切换、恢复区域、玩家预览，以及作者Ctrl+Z/Ctrl+Y已做实机验证；独立第二客户端、多作者同时编辑和不同光影组合仍需在各自整合包中测试。

## 10. 源码项目里的素材与构建（维护者）

| 项目相对路径 | 用途 |
| --- | --- |
| `build/libs/biyi_atlas-0.1.0.jar` | 构建产物，提供给使用者安装 |
| `tools/atlas_mcp.py` | 可单独随作者工具包分发的MCP脚本 |
| `src/main/resources/assets/biyi_atlas/` | 随JAR打包的语言、物品及默认纹理等 |

| `docs/art/region-1-v11/` | 本次示例区域的底片、manifest、两版美化原稿及提示词，不会因放在这里自动进游戏 |
| `docs/art/actual-*.png` | 开发时保存的实际截图/预览证据 |
| `recovery/` | 开发时的定点恢复备份，不是正常安装必需文件 |

仅替换公共贴图优先使用资源包；修改代码后才需要重新构建。维护者使用JDK 17，在项目目录运行：

```powershell
.\gradlew.bat build verifyTerrain
```

首次构建需获取Gradle/Forge依赖。项目当前 `gradle.properties` 中的本机JDK路径应按自己环境调整。Gradle构建包含 `reobfJar`，发布 `build/libs/` 中的最终JAR，不要发布开发类文件。`verifyTerrain` 包含地形、布局、图库和编辑历史回归；它不能替代实际游戏验收。

旧版专项笔记保留在项目中，若操作与本README冲突，以本README和当前界面为准。
