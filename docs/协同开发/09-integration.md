## 实施与交接

1. 接管 00 共享文件，把组件接回 M、HUD、玩家/作者全屏、权限变化、登录退出与 MCP。协议与存档变化从 05 合入；按已发布契约处理冲突。新模块只有经正常入口可达才计入交付。
2. 每批用作者与独立普通账号跑共同契约验收链；截图记场景、角色、版本与位置。实测冷/热开图、快速缩放、采样期间帧时与服务器 tick；报告机器配置、样本与前后对照。无实机记录则列待测。
3. 复测 F1、GUI 缩放、光影、热键冲突、无 JourneyMap、空工程、锁定区、协议不匹配和旧地图背包。用存档副本做删除、重进、迁移、从旧包回退。发布物标识源码版本、JAR 和 ZIP 哈希，区分模组与地图工程。更新玩家/作者 README。
4. 正常构建从项目根运行以下命令。使用 Java 17；GPU 原生库目录和工程包参数换成当前测试副本的真实路径。

   ```powershell
   .\gradlew.bat build verifyTerrain
   .\gradlew.bat verifyFogShader "-PlwjglNatives=<LWJGL原生库目录>"
   .\gradlew.bat verifyProjectBundle "-PverifyBundle=<工程包副本的绝对路径>"
   python tools/test_atlas_mcp.py
   ```

   可用已有本地 Gradle 缓存离线构建。GPU 验证需可用原生库，工程往返需输入 ZIP，双端、帧时和 UI 验收另行实测。
