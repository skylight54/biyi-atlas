**最省人力的开法**是先开总控，之后开三个对话分别做 01、02、03，先拿到可玩的地图。采样和发布有独立开发人手时可提前开发；第一批 UI 沿用现有已发布数据。下一批新开对话时，从包含全部前置任务的集成版本开始。06 和 08 就绪后都可以独立交付，07 先走地表，最终由 09 补验局部楼层的美化。

## 哪些行为必须一致

1. **入口与身份。** 右上角 HUD 随玩家移动，M 为默认开图键并可重绑。已知具备编辑授权的创造玩家进工作台；其余正常 M 入口进玩家图。维护命令仍按服务端权限处理。退役手持图渲染及 Shift＋右键，旧地图注册 ID 保留读取兼容，许可证继续解锁。小地图、区域、总览各有镜头。个人显示设置在两种界面左上角打开。
2. **三种图面。** 实景参考由本模组读取世界，供作者圈区；生成底图是玩家保底，选用的美化图是可选展示。位置、道路、水陆、建筑和入口共用真实世界坐标。云墨、追踪、道路、图标按可见性在运行时叠加。原生参考的首屏须能在没有区域、没有 JourneyMap 缓存时打开。
3. **数据生效。** 采样完成、图块可预览、作者选用候选、服务端发布成功是不同事件。作者能逐步看见草稿，玩家接收已发布且可见的数据。无需靠重新解锁触发刷新。重试同一提交不重复生效；旧客户端快照或晚到的响应不能让已删除的对象重新出现。
4. **兼容与范围。** 保留亚当、落日的区域 ID、世界坐标、现有路网、撤销与候选。局部楼层允许渐进迁移旧整数层。工程 ZIP 能在另一实例复现地图；世界方块及玩家个人解锁沿用原有分发边界。具体协议、格式的变更由 05 统一落地。
5. **实机判断。** 设计稿中的示例进度、建筑名称、楼层和区域排布只用于说明交互。实现用实际数据，待加载、无数据、失败和无权限都要有真实状态。分支用夹具开发时说明覆盖范围，最终验收使用正常入口与独立普通账号。

## 基线、交接与合并

协作仓库为 [skylight54/biyi-atlas](https://github.com/skylight54/biyi-atlas)。以 `main` 保存已集成版本；总控交出 00 的提交号后，功能对话从该号建立独立工作树或克隆，如 `feat/01-hud`、`feat/02-player`、`feat/03-editor`。提交或 PR 附任务 ID、起始提交、测试和接线需求。00 之前的首次源码导入只是版本起点。[文件指纹清单](baseline.sha256)覆盖生产源码、测试、资源、构建入口和工具。Git 检出可能转换行尾，清单对源码文本按 LF 核对、对二进制按原始字节核对。

**同一个可写目录分给多个对话会互相覆盖。** 临时使用隔离副本时，从同一提交取出，交付相对路径补丁，同时列出新增、修改和删除，再由总控在目标版本上核对并合入。

每批交付由总控公布一个可复现的基线编号。功能负责人从分配的独立目录开工，以一条交接消息返回下面的内容。状态表由总控维护，各分支交回消息即可。

```text
任务 ID / 起始基线 / 提交号或相对路径补丁位置
已打通的游戏入口与实际行为
改动文件（新增、修改、删除）/ 公共入口需要的接线
依赖的接口版本 / 对旧数据、缓存、协议及权限的影响
运行的命令、结果、复测步骤、角色、截图或日志位置
尚未验证的情况 / 回退方法 / 下一接手任务
```

**交付判定**分三步。功能对话交付独立实现与针对性验证后记“待集成”；09 从正常入口复测后记“已集成”；通过对应批次的普通玩家、作者和跨实例场景后记“已验收”。总控保留上一已验收构建和对应数据副本。分支开发与测试使用各自副本，统一由总控处理目标整合包的最终部署。

## 分批验收与回退

| 检查点 | 需合入 | 通过条件 |
| --- | --- | --- |
| A · 先玩起来 | 00、01、02、03 | 既有底图上，空手进亚当 → HUD → M → 点地标/个人路标 → 总览 → 返回。跨边界倍率稳定；普通玩家无编辑入口，创造作者能圈选、撤销并用玩家视角检查。 |
| B · 原生制图 | A、04、05 | 在无 JourneyMap 的空工程中获取实景、圈区、增量生成、取消再续、发布。独立普通账号能立即看到允许的底图；断线、乱序、重复提交后仍指向正确版。副本删除测试区域后重进与旧客户端重连都不会复活。 |
| C · 地标与美化 | B、06、07 | 用房屋、桥头两端、巨树根部入口在游戏中对照；无 AI 也可导航。故意错位的候选能标问题并回退。保留历史候选并选用一张，导出再导入后选用结果与地理坐标一致。 |
| D · 楼层与放行 | B、08；最终合并 C | 同一 XZ 的根殿与冠桥分别显示；只能沿真实入口跨层，离开后回到邻近单层区。普通客户端只收已解锁层。完成 A–D 全量复测、旧工程导入、专服重连、性能对比和回退演练。 |

失败时保留上一已发布版本，记录失败时的任务号、版本和复现步骤。UI 改动用 MCP 或截图核对正常界面；作者的玩家预览只能验证画面，服务端下发范围用独立普通账号验证。构建与测试命令见 [09 集成卡](09-integration.md)。
