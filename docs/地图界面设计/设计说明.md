# 避役图志 · 从游戏 HUD 到制图工作台

2026-11-27 设计评审稿，适用于现有 Forge 1.20.1 项目。[浏览全部 15 个界面](公开预览/README.md)。图集目录可以打开单张画面，SVG 中的游戏控件为静态设计。公开预览使用虚构地形，亚当与落日的真实对照素材保存在作者本地，地标、楼层、计数和任务状态用于演示交互。本文描述的新版入口、原生实景采集和局部楼层均待实现。

## 从玩家的操作开始

进世界就能在右上角看见小地图，中心是玩家，边缘标出北向。跨过大区边界时继续跟人，区外以云墨遮住；回原区时倍率保持不变。小地图倍率、大地图区域镜头、世界总览镜头各自保存。调整 HUD 倍率、进入楼层或接受新图块都不应改变另外两种镜头。

按 M 打开所在区域。标题给出地区，左下角显示探索进度；左上角永远是设置，右侧留给缩放与回到自己。进入总览后能看已知地区的位置与关系，点一个地区再进入。若人在已知地区之外，打开以玩家位置为中心的总览，显示最近的可见地区；首次登录尚无可见地图时保留定位和云墨，并提示“尚未发现区域”。收到地图数据后在当前镜头补图。

| 游戏场景 | 玩家看到的内容与操作 |
| --- | --- |
| [日常行走](公开预览/01-hud.svg) | 小地图默认右上角。显示本人、可见地标和当前追踪目标。进全屏后收起 HUD，回来时恢复。按 F1 隐藏界面时一同隐藏。 |
| [打开区域图](公开预览/02-region.svg) → [退到世界总览](公开预览/03-world.svg) | 玩家先看所在区域与可发现的地标；总览按真实世界坐标排布。返回区域保留先前镜头，“定位”才回到玩家。 |
| [发现地标](公开预览/13-place.svg) → [解锁反馈](公开预览/15-unlock.svg) | 点地标出现锚定在旁边的小卡片，“追踪入口”使用可步行的入口。服务端确认解锁后沿用开图、聚焦和云墨消散演出；可跳过、可回看探索进度。 |
| [在地图留个人路标](公开预览/04-pin.svg) | 点空白处弹出名称、图标、保存和取消。点已有路标可以编辑和删除。拖动超过阈值只平移。卡片自动翻到落点另一侧，靠近屏幕边缘时收进可视范围。 |

生存、冒险与旁观默认进游玩界面。创造模式按 M，在收到服务端编辑能力后进作者工作台。等待授权时先显示玩家可见内容。建议保留现有显式作者命令，供有权的非创造管理员维护；平时按 M 仍按游戏模式分流。创造作者可以临时进入“玩家预览”，选择锁定状态做只读检查。若服务器中途收回编辑权，退出写入工具，保留未提交草稿供恢复，停止传送作者图块。角色切换或离开世界时清理作者缓存和待处理请求。

## 作者只在需要时看见相应工具

顶部固定“设置、当前工程位置、玩家预览、发布、关闭”。左侧是可收起的对象树，中间是画布，点对象才出现属性。画边界时显示顶点、完成、取消、撤销，结束后回到浏览状态。旧界面同时平铺“工具、区域、路标、属性、视图、设置、MCP”，也从两处提供画区域。新界面按对象归属和编辑阶段收口。

| 操作 | 新的入口与归属 |
| --- | --- |
| [圈区与管理对象](公开预览/06-workbench.svg) | 区域树选中维度或大区后“新建区域”；选中大区后可建子区。面包屑显示所属地区。大区管地图范围、发布、候选；子区管局部边界、解锁和楼层。改父区时检查同维度、包含关系与循环；列出受影响楼层、地标和道路，再保留原世界坐标迁移。 |
| 放置地点、路标、道路 | “添加要素”收纳地标、作者公共路标、道路和跨层通道，各自只出现所需属性。路网吸附和记录路线归入道路工具；移动顶点、删除、撤销归当前选区。私人的点位留在玩家路标卡。 |
| [采集与生成](公开预览/14-survey.svg) | 选区域后看已有覆盖，补采缺口；任务显示覆盖率、失败图块、取消、继续与重试。作者先看已完成图块，玩家继续看已发布版本。 |
| [特殊地标确认](公开预览/08-landmark.svg) · [局部楼层编辑](公开预览/10-floor-editor.svg) | 前者管“它是什么、占哪块地、从哪进去”；后者管“哪一层能走、两个入口是否相通”。选择普通单层地标时收起楼层工具。 |
| [美化校对](公开预览/11-art-review.svg) → [预览与发布](公开预览/12-publish.svg) | 候选从大区的“展示方案”进入，可看多张、对照、保留、回退；发布前可用底图交付。把选用候选与发布分开，导入新候选先进入草稿。收到服务端版本回执后才标记已发布。 |
| [设置与权限](公开预览/07-author-settings.svg) | “个人显示”与玩家相同。“制图与权限”增加参考图采样策略、服务器给出的预算、MCP 状态和最近任务、工程导入导出。地图边界、楼层和候选放在选中对象属性中。服务端在每次读取作者资料和写操作时重新判权。 |

画布采用浅灰水墨与墨青工具栏，柔金表示主动作，朱色标出当前玩家或待修轮廓。地名用细描边；小区域边界只在相应编辑工具中显示。玩家详情卡目标宽度约四分之一屏；窄屏使用贴底的紧凑卡片，可展开长说明。按钮始终保留文字，当前所处楼层、待复核和已发布状态也用文字说明。Esc 优先关卡片或取消未提交手势，再退一级；关闭大地图才回到游戏。

## 三种地图画面，使用同一套世界坐标

| 图面 | 数据与用途 | 谁能看 |
| --- | --- | --- |
| 方块实景参考图 | 直接读世界方块。地表记录顶面可见方块的地图色、树冠、水面与高度明暗，近处可见屋顶边缘。指定 Y 带改采楼层内可通行面。进入空工程时先显示作者附近已加载区块，未测处画网纹；可框选临时矩形补采，再按实景精确圈区，解决“必须先有区域才能看参考”的循环。 | 作者专用，按当前视窗和清晰度取瓦片。安装本模组即可圈区。 |
| 生成底图 | 从实测数据确定水陆、地势、建筑足迹和通行面，生成可重复绘制的水墨地图。道路、地名、玩家、入口和解锁遮罩由运行时叠加。 | 玩家取当前区域、楼层、可见范围内的已发布瓦片；作者可看生成中的草稿。 |
| 美化展示图 | 同一地理范围与像素变换内，润色材质、山体明暗、水纹和建筑笔触。多候选保留，按区域及适用楼层选用。候选缺失、过期或局部对照失败时，使用对应底图。 | 玩家只取选用且允许可见的结果。作者持有候选和几何对照工具。 |

同一层内切换三个画面要保留镜头、十字坐标和已选对象。底图与展示图共用维度、区域边界、楼层、世界原点和比例。局部楼层是空间范围，每一层又能选上表的画面类型。这样作者可以一边检查“树冠层的方块实景”，一边给玩家发布“根殿层的水墨底图”。

**已有基础。** `JourneyMapImport` 与 `AtlasScreen.renderJourneyUnderlay` 读取外部图片给作者作参考。现有区域生成另有自己的 `SurfaceSurvey` 和服务端准备任务，目前整区准备限主世界地表层 0。建议先实现“离开 JourneyMap 后仍能从空工程完成圈区”的有限原生参考能力：地表俯视、平移缩放、坐标、已测覆盖与限定范围补采；随后再交付局部切片。保留旧区域、道路和工程包坐标。 [现有参考图读取](../../src/main/java/com/biyi/atlas/client/JourneyMapImport.java) · [现有区域制作流程](../../README.md)

**加载做法。** 先返回任务号和现有覆盖，再分批交付完成的瓦片。游戏线程按每刻预算读取已加载区块数据，后台只处理不可变快照并编码；相邻瓦片带采样余边，约定唯一边界像素，避免接缝。默认只扫描已生成区块；作者明确选择扩展世界后，才允许任务生成新区块。缓存键包含工程/世界、维度、图面、区域或参考网格、局部层、分辨率和版本。低清先显示、视窗外取消排队、缓存设上限。HUD 与大图共用合法缓存，各自保存镜头；玩家端收不到作者实景、未解锁几何或整张未裁剪候选。重连和快速切区用请求版本丢弃过期回包。

## 建筑为什么会丢，怎样把巨树画对

现有采样每 4×4 方块存一份地表高度和类别，并逐列生成 16 位建筑掩码，能保留一部分逐方块的屋顶轮廓。判断依赖木板标签、材料匹配等规则；地表查找会跳过树叶和多数原木。导出的 `base.png` 把建筑涂成浅色，`manifest.json` 带世界范围、形状与底图指纹、方向、采样统计等信息。外部 AI 根据这些输入与作者提供的说明生成候选，模组再校验、裁切并登记。现有整体仿射配准能修整体偏移；建筑入口、桥头和树冠语义的信息仍可能在采样或重绘时丢失。 [实际采样](../../src/main/java/com/biyi/atlas/map/SurfaceSurvey.java) · [实际底片导出](../../src/main/java/com/biyi/atlas/map/PresentationExporter.java) · [历史配准记录](../第十九批-美化图坐标配准.md)

建议先交付一个不依赖 AI 也能画准的建筑流程。

1. **采两种表面。** 同时保存顶面与地面高度、顶面材料类别、树叶/原木覆盖，保留现有建筑掩码。对作者框选的复杂点再细采高度剖面与可走平台。支持数据包补充模组方块标签。
2. **给出可修订的候选足迹。** 连通材料、屋面高度突变、重复直边和平台用于找房屋；狭长的跨水通路用于建议桥梁及两端。天然峭壁、模组材料和树屋容易误判。作者可圈选、拆分、合并、忽略，也可从零手绘，确认才参与发布。
3. **把特殊地标交给作者定名。** 在亚当的巨树处框出树冠，点一下树干作定位锚点，再单独点根部真实入口。树冠巨大且包含平台时可提示“高冠结构”，由作者选“巨树建筑”，并给出根部、树冠高度带。近景依照冠缘画枝叶轮廓，远景缩为树印。地图上的图标落在树心，引路终点落在入口；这两点可以相距几十格。
4. **先固定几何，再润色。** 导出底片时附同尺寸水陆、岸线、水系、建筑轮廓、桥头、入口及禁止覆盖区。按遮罩分区着色，将受保护轮廓与道路接点按真实坐标重新合成。作者用并排对照或滑动分割检查，记录问题面。第一批样本建议要求桥头与入口点在一个细采方块内，主要建筑逐边对照；岸线限制在原采样分辨率内。门槛是验收建议，历史候选需重新复核。底图指纹或局部楼层定义改变后，只使相关候选失效并保留源图。

## 纵向复杂地区使用局部楼层

区域树表达地理归属，例如「主世界 → 亚当 → 冠木庭」。冠木庭可以只有根殿与冠桥，同属亚当的港镇可以是码头、街面与地窖，野外只显示地表。两地同名的“一层”没有关联。旧工程只含整数层号时，读取时保留原层及相对顺序；由作者逐区绑定新楼层、复核锚点后再升级副本。

每层存稳定 ID、所属子区、XZ 轮廓、可命名高度带、可通行平面或人工修订、默认入口、通往其他层的出入口。楼层内容和展示图都绑定稳定 ID。通道保存双端的坐标、楼层和方向；相同 XZ 的两个点只有通过楼梯、坡道、电梯等明确连接才可跨层导航。自然地面保留父区底图；切到地下时只替换局部边界内画面。楼层未配置美化时沿用该层底图，地下数据还没采到时在作者端标出缺口。

自动选层先判子区轮廓，再看玩家脚下可走面与 Y 带。楼梯间高度重合时优先保留上一层，越过作者标的入口后切换；离开子区回到父区，倍率不变。平移浏览不触发玩家自动换层。若两个候选都合理，给玩家可见的手动切层入口。作者能在同一 XZ 叠看两层、修订范围和连接；普通玩家只收到已发现层的信息。

## 迁移顺序与验收

| 批次 | 交付与验收 |
| --- | --- |
| 1 · 日常探索 | 移除持物检查、双手举图与 Shift＋右键设置入口，用 HUD 与角色化 M 键代替。旧 `biyi_atlas:atlas` 建议暂留无交互的注册项，退出创造物品栏和获取入口，兼容背包、箱子和旧脚本；区域许可证继续承担解锁。验证空手、双手持其他物品、跨界重入、重新登录、小地图与全屏分别缩放。创造→生存即时收回作者界面，普通账号实测无写权限。 |
| 2 · 脱离外部参考 | 在无 JourneyMap 且无历史外部瓦片的实例，从空工程看到附近实景、框选补采、圈区、生成、预览、发布；另一台普通客户端仅凭服务器内容开图。验收冷开、连续缩放、任务取消复跑、只补变化区块、离线重进与区外遮罩。 |
| 3 · 建筑与展示 | 用普通房屋、跨水桥、手建巨树做标注→确认→对照→发布；保留原亚当和落日候选。用实际入口导航并在游戏中走到桥两端。用故意错位的副本确认能标记问题和回退，正式工程包在另一实例复现同一展示方案。 |
| 4 · 局部纵向探索 | 做一棵树的根殿/冠桥和相邻的单层野外，在同一世界坐标切实测不同高度，走树梯跨层，再去相邻子区。检查层选择、解锁、导航、旧数据迁移和导出重导入。记录 HUD 开关、冷/热开图与生成期间的帧时和服务端 tick，再据实测调采样预算。 |

最小可玩的验收路线是「空手进亚当 → 看右上角小地图 → M 找到冠木庭 → 点卡片追踪真实入口 → 解锁并查看探索进度 → 走出边界再回来」。这条路线可以先用已发布的底图跑通，再将同一角色、同一镜头用于验证巨树美化与局部楼层。
