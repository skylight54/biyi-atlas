# 地图工程分享（2026-10-22）

本批需使用协议5的同一份模组。普通玩家无导入/导出权限。地图工程是本模组的数据包，不含Minecraft世界方块。

## 推荐流程

1. 在原地图存档完成编辑、美化候选选择及底图生成，等待“内容已同步到服务端”。
2. 作者界面的“导出完整地图工程”导出固定名`shared`；也可输入`/biyi_atlas_local export_project mymap`，这个客户端命令会先提交当前编辑，再请求导出。
3. 在`<实例>/biyi_atlas/projects/`取得`mymap.biyi.zip`。不要拆包逐个找文件。
4. 把这个文件和使用的同版模组给接手作者；目标需要同一Minecraft地图存档/相同坐标地形及外部模组、资源包。
5. 接手作者把ZIP放进自己实例的`biyi_atlas/projects/`，进入目标单人世界，输入`/biyi_atlas project import mymap`。工程名只使用字母、数字、下划线或连字符。
6. 导入会替换当前地图工程，先备份旧文件到`biyi_atlas/project-backups/<编号>/`。完成后退出世界再进入，刷新自定义图标、路标和地形缓存。保存后可继续编辑、删除区域并再导出给下一位作者。

单人及局域网主机支持导入；专用服务器当前拒绝在线导入，避免把服务器文件误当成客户端资源。专服迁移仍需停服并配套分发自定义资源。服务端命令`/biyi_atlas project export mymap`也可导出已同步内容，不能提交尚在客户端的草稿。

## 包含什么

- 完整区域/层级、道路、地点、删除墓碑及兼容字段。
- 服务端已发布底图，所有美化候选、图库索引和当前选择。
- 当前世界的作者自定义图标、导入图片、地点图资源。
- 当前世界本地地图NBT（含路标）。不包含每个玩家的解锁账本。
- manifest.json：格式号、每个文件的SHA256和未准备完整的地图范围警告。

导入前检查路径、文件数量、总大小及哈希；256MiB解压总量上限。旧地形/作者素材目录整体移入备份，避免同区域id的旧底图/候选残留。每一份原图库都保留在备份中。

工程包不会生成缺少的底图。请检查清单的`warnings`：未发布或未生成完整的区域会列出来。外部资源包/模组及世界方块不打进ZIP，接收方仍需配齐。自定义纹理来自外部资源包时仍需一同提供原资源包。

## 美化图在哪里

正式使用的美化图在**世界存档内**：

`<世界目录>/data/biyi_atlas_terrain/<区域id的SHA256>.art.nbt.gallery/`

其中`index.nbt`记录候选名与当前选择，每张候选保存在独立NBT里，PNG作为字节数组存放。旧版`<hash>.art.nbt`兼容文件也保留。旁边的`<hash>.nbt`是真实地形底图。不要只复制PNG或只复制索引，否则会丢候选或配准指纹。工程ZIP会一起带走。

AI导出的素材与临时上传位于`<实例>/biyi_atlas/ai_bridge/`；开发时的原始美术源图位于开发项目`docs/art/`，二者都不是玩家运行时必须依赖的正式图库。

## 本批其他修正

作者请求底图不再依赖区域已解锁，加载请求会登记活动区域，完成后直接发给作者；生成过程每5秒发送一次预览快照（不是每个区块立即发包），只在完成后正式发布。中间预览不会将半成品当作完整美化底图。

删除墓碑阻止迟到的服务端几何重新加入；上传包含完整可编辑视图，权威快照不再叠加旧配置中的同名区域。图鉴入口与旧图鉴魔杖操作停用，旧数据保留作存档兼容。

地形图块增加1像素真实邻接外扩，缓解线性过滤时边缘夹取产生的接缝；手持边框增加不透明的旧纸暗边和磨损。视觉效果、他人实例的重进持久化以及生成中预览仍需实机验收。
