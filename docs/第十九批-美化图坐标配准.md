## 问题与修复

用户实拍与MCP088fb84c确认：亚当选中的第二张生成图仍与实际地形不完全对应；区域轮廓15个顶点与导出清单完全相同，shape/base匹配，但这只能证明版本匹配，不能证明AI内部地形没有移动。第一次图像生成出现纵向压缩；再次图像编辑在不同位置修正幅度不一致。因此增加独立于区域、道路与标记坐标的候选图像配准。

原manifest可额外携带`registration: [a,b,tx,c,d,tz]`。源图与地图都采用完整画布归一化坐标，左上为(0,0)，右下为(1,1)：

```text
mapX = a * sourceU + b * sourceV + tx
mapZ = c * sourceU + d * sourceV + tz
```

未设置时为[1,0,0,0,1,0]。限制有限数值、正向缩放、有限剪切与平移，拒绝翻转/奇异变换。渲染使用逆映射与连续浮点UV，仍裁剪在原区域，越出源图范围显示保底地形而不是循环拉回另一边。按行构建三角形并批量提交，替代逐行独立blit；保存恢复混合、深度、剔除、纹理和shader状态。

服务端按校准后像素的实际世界坐标执行已知采样/区域裁剪；候选NBT携带校准参数，工程ZIP自然包含。候选id加入原PNG、shape、base与配准矩阵，修复同一PNG不同配准或不同底图被当成同一候选的问题。旧候选保留，加载时按恒等映射处理，不改写旧索引。
